# addons/surface_maps
What: guesses a relief from a colour picture and saves it as maps a material can use: a normal map (OpenGL, green up) and, on request, an ORM (R occlusion, G roughness, B metal or height). Generic (no game rules) and dev only: the export excludes it and nothing in `scenes/` or `data/` refers to it.
Not: how a model looks in a match (its `StandardMaterial3D` `.tres` is the only owner), the ground's shader, Material Maker graphs (tools/material).
Talks to: `ReliefRecipe` (the knobs) -> `ReliefBaker.bake(image, recipe)` (pure pixels, NormalMap-Online's algorithm: brightness -> [invert] -> [high-pass, off by default] -> smoothing / sharpen -> 3x3 Sobel or Scharr slope -> normalize(slope * 255, (1 + 2^level) / strength), OpenGL; cavity occlusion; cutout fill; per-tile wrap) -> `MapWriter` (path, PNG + `.import`, assign with `EditorUndoRedoManager`). `plugin.gd` adds the settings `surface_maps/mirror_from` / `surface_maps/mirror_to`, the inspector section (`surface_inspector` -> `surface_panel.tscn`, knobs from `recipe_form`) and Project > Tools > «Generar relieve…» (`batch_dialog.tscn`); both go through `relief_job` and share one recipe per editor session. CLI: `tools/bake/bake_relief.gd`.
Edit: the two presets in `recipes/` (`default.tres` = the script's defaults; `foliage.tres` = smoothing 1, for thin leaves that speckle; pass one to the CLI with `--recipe=`); the recipe's defaults in `relief_recipe.gd` (NormalMap-Online's: strength 2.5, level 7, smoothing 0, Sobel; high-pass off; no ORM, roughness 0.85, metallic 0); where maps go in Project Settings `surface_maps/*`; the maps themselves are PNGs under `assets/surfaces/` (retouch them in any image editor).
Check: rules_suite `surface_maps_cases` + `surface_refs_cases` (determinism, flat, ramp signs, invert, Scharr, cutout halo, paths) · F6 `debug/look/surface_lab.tscn` (the light orbits; O pauses, U turns, I tilts) · `Godot --headless --path . --script res://tools/bake/bake_relief.gd -- <material.tres>` · in the editor: `scenes/bodies/materials/eorc_001.tres` > «Relieve desde albedo» > Generar, then Ctrl+Z.

---

How a human uses it:
- One material: select it (or a model's surface override, or a ground role inside `data/look/<god>.tres`), open «Relieve desde albedo» at the top of the inspector, move the knobs (the right picture previews the relief), press Generar and save with Ctrl+S. It writes the PNGs that are missing, imports them and assigns them in one Ctrl+Z step. A PNG that exists is used as it is; «Sobrescribir» bakes it again (and loses what you retouched). Quitar takes the maps off in one Ctrl+Z step; the PNGs stay on disk.
- Many: Project > Tools > «Generar relieve…», pick a folder (or «Selección» for what the FileSystem dock has selected), keep «Saltear existentes» on and press Generar. It shows the progress; «Detener» stops after the current material. Each material is saved to disk, so there is no Ctrl+Z (version control or Quitar take it back). A material embedded in a scene is assigned but not saved: save that scene.
- Turning every map off (or on) at once, in the game: the quality preset (`relief_maps` in `data/look/quality_<low|medium|high>.tres`; low is off) or the player's option Opciones > Gráficos «Relieve (mapas de normales)». Both act in memory (`scenes/look/surface_relief_layer.gd`); no material is saved.
- The recipe is the same in both places and lasts until the editor closes (never saved: the PNG is the source). Retouch a map in any image editor; Godot reimports it.

Where maps go: a picture under `assets/original/textures/<owner>/` gets `assets/surfaces/<owner>/<file>_normal.png` (and `_orm.png`); any other picture (your own content) gets them beside it. A PNG that exists is never replaced unless you ask (`overwrite`, `--force`); its `.import` is written only the first time (VRAM compressed, mipmaps, `compress/normal_map=1` for the normal, `detect_3d/compress_to=0` so the editor never rewrites it), so its uid and your import settings stay.

Assigning: on a `BaseMaterial3D` the normal goes to Normal Map (`normal_enabled`), the ORM to Ambient Occlusion (channel R) and Roughness (channel G, `roughness` set to 1 because Godot multiplies them). Metallic is left alone: with the default metallic 0 there is nothing to show. Any other Resource with `normal` / `orm` Texture2D fields gets those fields. A material can be shared by several models: its maps show on all of them.

Turning the relief upside down: `invert_height` in the recipe, or a negative `normal_scale` on the material. `invert_r` / `invert_g` flip one axis (`invert_g` gives DirectX, green down; Godot reads OpenGL). Softer: lower `strength` or raise `level`, or `normal_scale` on the material; less speckle on a busy picture (leaves): `smoothing` 1-2.

References:
- NormalMap-Online (cpetry, MIT): https://cpetry.github.io/NormalMap-Online/ , source https://github.com/cpetry/NormalMap-Online (`javascripts/normalMap.js`, `shader/NormalMapShader.js`) — the algorithm ReliefBaker ports: grey height, Sobel / Scharr, dz = (1 + 2^level) / strength, defaults 2.5 / 7 / 0.
- Godot `BaseMaterial3D` (normal map is OpenGL, Y up; ORM is R occlusion, G roughness, B metal): https://docs.godotengine.org/en/stable/tutorials/3d/standard_material_3d.html
- Godot texture import (`compress/normal_map`): https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html
